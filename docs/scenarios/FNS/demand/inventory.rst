Опись — ответ на требование
===========================

Опись необходимо прикладывать не только к некоторым налоговым декларациям, но и в ответ на требования с КНД 1165050, 1165013, 1152006, 1153007 и 1125008. Опись ссылается на требование, в ответ на которое она формируется, и включает список файлов, высылаемых в налоговую. При отправке опись имеет свой тип документооборота urn:docflow:fns534-inventory.

Чтобы отправить опись и следить за документооборотом с налоговым органом, необходимо знать три параметра:

* ``inventoryId`` – идентификатор документооборота описи;
* ``relatedDocflowsId`` – идентификатор входящего документооборота, в ответ на которое присылается опись;
* ``relatedDocumentId`` – идентификатор документа требования из входящего документооборота. 

**Зачем обязательно создавать опись?** Если создавать новый документооборот, например, письмо с набором документов, то в информационных системах ФНС он не будут связан с требованием. Тогда не будет соблюдено требование законодательство по срокам ответа. 

Подготовить опись в ответ на требование поможет конструктор черновиков :doc:`DraftsBuilder</scenarios/device_api/DraftsBuilder>`. Сервис приведет приложенные сканы изображений по требованиям приказа ФНС РФ от `18.06.2025 N ЕД-7-26/535@`_. А если файлов много, то разобьет их на связанные черновики. Алгоритм создания описи смотри в разделе ниже :ref:`"Процесс работы с описью"<rst-markup-inventory-work-process>`.

Согласно приказу ФНС РФ от `18.06.2025 N ЕД-7-26/535@`_ отсканируемые приложения должны быть:

* в одном из форматов: .pdf, .png, .jpg, .tif;
* черно-белые;
* с разрешением не менее 150 и не более 300 точек на дюйм;
* градация серого цвета: 256. 

Ограничения для файлов при подготовке описи в конструкторе черновиков DraftsBuilder:

* можно приложить не более 99 файлов;
* суммарный объем черновика может быть не более 60 Мб.

После успешной отправке описи будет создан документооборот с типом urn:docflow:fns534-inventory. Для работы с самим документооборотом описи и ответными документами в нем смотрите методы в :doc:`разделе "Ответ на требование"</inventories/методы до описи>`.

Процесс работы с описью
-----------------------

.. image:: /_static/invent_proc.png

.. note:: 
    Если файлы не соответствуют нужному формату, то подпись нужно прикладывать к файлам после шага 4 – этапа сборки DraftsBuilder.

    Если файлы уже приведены к нужному формату и есть XML-файл описи к документам, можно пропустить шаги 1-4 по работе с DraftsBuilder и сразу работать с методами черновика документооборота.

1. Создание DraftsBuilder методом :ref:`POST CreateDraftsBuilder<rst-markup-createDB>`

 Метод создает шаблон черновика описи: для этого нужно передать идентификаторы входящего документооборота и документа в нем, а также пункт требования. Если ответ на требование необходимо отправить через уполномоченного представителя, укажите в параметре ``machine-readable-warrant-id`` идентификатор машиночитаемой доверенности.
 
 В результате метод вернет идентификатор созданного шаблона DraftsBuilder и все его содержимое. 
 
Пункт требования можно прописать на весь DraftsBuilder — глобальный, а можно на конкретный документ — выборочный. Пункт требования в документе более приоритетный, но если он не заполнен, будет взято значение глобального параметра. Хотя бы в одном месте пункт требования должен быть заполнен обязательно.

2. Добавление документа :ref:`POST CreateDraftsBuilderDocument<rst-markup-createdocDB>`

 Чтобы добавить файлы, необходимо сначала добавить для них контейнер — документ. Вызываем столько раз, сколько отдельных документов-контейнеров нужно создать.

3. Добавление файла :ref:`POST CreateDraftsBuilderDocumentFile<rst-markup-createfileDB>`
 
 Метод создает файл в документе. Вызываем столько раз, сколько файлов нужно положить в документ-контейнер.

4. Сборка DraftsBuilder :ref:`POST BuildDrafts<rst-markup-buildDB>`

 Метод собирает все добавленные файлы и документы DraftsBuilder шаблона в черновики. В результате метод вернет идентификаторы черновиков, в каждом из которых находится: XML-файл описи, файлы, сообщение о представительстве (если есть).
 
 Для редактирования содержимого DraftsBuilder смотри описание :doc:`методов DraftsBuilder</builder/методы билдера>`.  

5. Работа с черновиком. 

 Черновик описи проверяется, подписывается КЭП и отправляется при помощи методов :doc:`для работы с черновиками</drafts/index>`. После отправки черновика вы получите идентификатор документооборота описи с типом urn:docflow:fns534-inventory. 

6. После отправки описи необходимо отслеживать процесс документооборота и его статусы, для этого были реализованы :doc:`методы документооборота описи</inventories/методы до описи>`.
