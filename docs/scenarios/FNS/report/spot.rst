Система подтверждения ожидания товаров. СПОТ
============================================

Что такое СПОТ
--------------

СПОТ — это система подтверждения ожидания товаров, которую правительство РФ запускает с 1 июня 2026 года. Система обязывает импортеров заранее уведомлять налоговую о предстоящей поставке, а перевозчиков предъявлять документы при прохождении таможни. Это касается товаров, которые ввозятся автомобильным транспортом из государств ЕАЭС. 

Цель СПОТ со стороны государства: 

* сократить серый импорт;
* пресечь налоговые схемы: поставки в адрес ликвидированных или неактивных российских импортеров, а также реализацию через лиц, применяющих УСН, без уплаты налогов.

Для документооборота ввели новый первичный документ — ДОПП с формой КНД 1160303. Полное наименование: «Документ о предстоящей поставке товара на территорию Российской Федерации и иные территории, находящиеся под ее юрисдикцией, с территории другого государства — члена Евразийского экономического союза».


Как будет работать СПОТ
-----------------------
.. image:: /_static/spot-scheme.png

1. **Импортер** согласовывает поставку с налоговой перед ввозом товара из ЕАЭС, заявляет о предстоящем ввозе товара и заранее уплачивает обеспечительный взнос в сумме НДС. До 31 мая 2026 года НДС уплачивается после поставки.
2. **Импортер** отправляет ДОПП по ТКС за 2 календарных дня до пересечения границы `п.1 ст.10 Законопроекта № 1175065-8-1`_. Это помогает избежать проблемы с отсутствием интернета, а ФТС заранее получает документы. 
3. **Налоговая инспекция** проверяет полноту информации в документе о предстоящей поставке товара и поступление обспечительной суммы, а затем направляет в ответ сформированный QR-код.
4. **Импортер** передает код перевозчику для предъявления при пересечении границы. При каждой последующей транспортировке товара нужно получать новый код, даже если будет выявлена неполная транспортировка товара.
5. **Перевозчик** получает от импортера ДОПП с QR-кодом. Перевозчик, например, экспедитор или водитель, должен иметь его при себе при ввозе товаров, чтобы предъявить его по требованию сотрудника таможни.
6. **Сотрудник таможни** на границе проверяет статус документа перейдя по ссылке из QR-кода, и принимает решение о разрешении или запрете ввоза товара.

Кто участвует в СПОТ
--------------------

Участники СПОТ — все организации и ИП на любой системе налогообложения, ввозящие товары автомобильным транспортом из стран ЕАЭС — Казахстана, Беларуси, Армении, Киргизии. Это сами импортеры и посредники.

Уполномоченные органы, задействованные в СПОТ:

    * Минфин — разрабатывает госполитику и нормативно-правовое регулирование.
    * ФНС — оператор СПОТ: прием и форматно-логический контроль ДОПП, учет обеспечительного платежа, актуализация статусов и присвоение QR-кода.
    * ФТС — контроль наличия QR-кода ДОПП у перевозчика при ввозе товаров из ЕАЭС.

На какие товары распространяется СПОТ
-------------------------------------

Это товары, ввозимые в РФ из государств ЕАЭС автомобильным транспортом, а также другими видами транспорта, если Правительство примет такое решение по результатам запуска СПОТ.

Требования СПОТ не действуют на товары `п.3 ст.5 Законопроекта № 1175065-8-1`_:

    * наличные деньги;
    * нефть и нефтепродукты;
    * электроэнергия;
    * товары, транспортируемые по трубопроводу;
    * товары, ввозимые физическими лицами для личных, семейных, домашних нужд;
    * товары, перемещаемые между Калининградской областью и другой частью территории РФ;
    * товары, сведения об операциях с которыми составляют государственную тайну;
    * товары, следующие в адрес диппредставительств, консульств, международных организаций, расположенных в РФ;
    * иные товары по перечню, утвержденному Правительством РФ после запуска системы.

Ожидается, что после успешного внедрения СПОТ обязанность оповещать налоговую о планируемой поставке распространится и на другие виды транспорта: воздушный, железнодорожный, морской, речной, но не ранее 2027 года.


Алгоритмы работы с методами API
-------------------------------
Создание и отправка черновика
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

1. Создайте черновик: :ref:`POST Create Draft<rst-markup-createdraft>`. При создании черновика укажите код ИФНС — ``infs-code``.
2. Загрузите файл ДОПП с КНД 1160303 в сервис контентов :ref:`POST Upload<rst-markup-post-content>`.
3. Создайте документ в черновике :ref:`POST Add Document<rst-markup-addDocument>`. В теле запроса передайте идентификатор загруженного контента ``content-id``.
4. Добавьте подпись к документу: :ref:`POST Add Signature<rst-markup-AddSignature>`.
5. Запустите последовательность методов, когда черновик будет готов к отправке: :ref:`POST Check<rst-markup-check>` -> :ref:`POST Prepare<rst-markup-prepare>` -> :ref:`POST Send<rst-markup-send>`.

    a. Укажите флаг deferred = true для отложенного выполнения задач.
    b. Каждый из методов возвращает task-id для отслеживания выполнения задачи.

6. Проверяйте результат выполнения задачи: :ref:`GET DraftTask<rst-markup-DraftTasks>`. Если операция Send завершилась успешно, при получении задачи в ответе возвращается информация о созданном документообороте типа представление ``urn:docflow:fns534-submission``. Далее нужно отслеживать данный документооборот и формировать ответные документы :ref:`согласно статусам<rst-markup-submission-status>`.

Работа с документооборотом представления
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Чтобы завершить работу с документоооборотом нужно:

1.	Отслеживать :ref:`статус документооборота<rst-markup-submission-status>` ``urn:docflow:fns534-submission``.

    1. ``sent`` -> ``delivered`` — контролирующий орган отправил Извещение о получении ДОПП (КНД 1160303).
    2. ``response-arrived`` — контролирующий орган обработал документ и отправил Квитанцию о приеме, либо Уведомление об отказе.

2.	На квитанцию о приеме или уведомление об отказе нужно отправить ответный документ — Извещение о получении. Для этого:

    1. Создайте ответный документ :ref:`POST CreateReplyDocument<rst-markup-post-reply-doc>`. В ответе метод возвращает информацию о сгенерированном документе и контент квитанции о приеме. 
    2. Подпишите квитанцию о приеме при помощи сертификата, установленного на компьютере пользователя. Либо при помощи сертификата: :ref:`POST CreateReplyDocument<rst-markup-post-reply-doc>` и `POST SignConfirmReplyDocument`_.
    3. Если подпись была сгенерирована на компьютере пользователя, приложите ее к ответному документу: :ref:`PUT ReplyDocumentSignature<rst-markup-repliSignature>`.
    4. Отправьте ответный документ: `POST SendReplyDocument`_.

3.	После отправки Извещения о получении статус документооборота сменится на ``finished``. Документооборот завершен.


Работа с квитанциями о статусе ДОПП
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

После получения квитанции о приеме на исходящий ДОПП нужно ожидать квитанцию о статусе (КНД 1167011). Она приходит в типе документооборота ``fns534-demand``. Алгоритм работы с требованием в API описан в статье :ref:`«Требование»<rst-markup-FNS-demand>`.

На один ДОПП может быть несколько таких квитанций, но QR‑код содержит только первая — со статусом «Обеспечен».
Документообороты со статусами содержат имя исходящего ДОПП в поле ``sent-on-report-filename`` для создания связки.
